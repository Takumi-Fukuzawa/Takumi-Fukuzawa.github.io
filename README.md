# キャンパスマップ情報システム

## 概要

このプロジェクトは、大学キャンパス内の建物や施設に関する情報を、**インタラクティブなマップ上で提供するWebアプリケーション**です。ユーザーは、検索機能やマップ上のマーカーを通じて施設情報を閲覧でき、デスクトップおよびモバイルデバイスの両方で最適化されたユーザーエクスペリエンスを提供します。

## システム構成

本システムは以下の5つの主要なファイルで構成されています。

*   **`index_HTML` (HTML)**: アプリケーションの骨格となるメインページです。IPアドレスによるアクセス制限のJavaScriptも直接記述されています。
*   **`style_CSS` (CSS)**: アプリケーション全体のレイアウト、主要なUI要素（検索ボックス、情報パネル、マップ、マーカー、モーダルなど）のスタイリング、およびレスポンシブデザインを担当します。
*   **`BottomSheet_CSS` (CSS)**: モバイルデバイスで利用されるボトムシート（下からスライドアップする情報表示エリア）に特化したスタイリングを提供します。ドラッグバーやコンテンツ領域のスタイルが含まれます。
*   **`app_JavaScript` (JavaScript)**: マーカーの生成、施設情報の管理 (`infoData`オブジェクト)、検索機能のロジック、情報パネル（デスクトップ用）の表示・操作、Googleマップ連携、フロアマップモーダルの表示など、アプリケーションの主要なインタラクティブ機能を提供します。
*   **`BottomSheet_JavaScript` (JavaScript)**: モバイルデバイス向けのボトムシートの動的な挙動（開閉、ドラッグ、スワイプ、コンテンツ更新、ズームリセットなど）を制御するロジックを提供します。

## 主要機能

*   **インタラクティブなキャンパスマップ**:
    *   大学のマップ画像上に、各施設を示す番号付きマーカーが配置されます。
    *   PC版では適切な座標に、モバイル版では表示サイズに合わせてマーカー位置が調整されます。
    *   マーカーをクリックすると、該当施設の詳細情報が表示されます。
*   **施設詳細情報の表示**:
    *   **PC版**: マーカークリック時、画面左に**情報パネル**が表示され、選択した施設の建物番号、名称、詳細説明、画像、およびフロアマップの有無（ボタン）が表示されます。パネルは最小化 (`━`ボタン) や閉じることが可能 (`✖`ボタン) です。
    *   **モバイル版**: マーカークリック時、画面下部から**ボトムシート**がスライドして表示され、PC版と同様の施設情報が表示されます。ボトムシートはドラッグ や下スワイプ で閉じたり、部分的に開いたりできます。
*   **検索機能**:
    *   キーワード検索（施設名、建物番号、関連キーワード）をサポートします。
    *   検索ボックスへの入力に応じて、リアルタイムで検索候補が表示されます。
    *   重複する検索結果を避けるためのロジックも含まれます。
*   **Google マップ連携**: 各施設詳細情報にはGoogleマップへのナビゲーションリンクが提供されており、クリックすると新しいタブで該当施設の地図が開きます。
*   **フロアマップ表示**: 建物によっては詳細情報内に「フロアマップ」ボタンが表示され、クリックすると平面図のモーダルウィンドウが開きます。
*   **レスポンシブデザイン**: ウィンドウサイズ（特に768pxを閾値として）に応じて、情報表示方法（情報パネル/ボトムシート）が自動的に切り替わり、PCとモバイルの両方で最適化された表示を提供します。
*   **IPアドレス制限**: アプリケーションは、セキュリティのため特定のIPアドレス範囲（例: 大学のWi-Fiネットワーク）からのみアクセス可能に設定されています。

## 開発者向け詳細

### 1. 情報データ構造 (`infoData`)

全ての施設情報は、`app_JavaScript.txt`内の**`infoData`オブジェクト**に定義されています。各施設はID（建物番号）をキーとし、以下のプロパティを持ちます。

*   `title`: 施設名
*   `text`: 施設の説明
*   `img`: 施設画像のパス
*   `floorImg`: フロアマップ画像のパス（フロアマップがない場合は省略）
*   `x`, `y`: マップ画像 (`assets/campusmap.png`) 上のマーカーのピクセル座標。**モバイルデバイスでは、これらの座標は内部的に1.5で割られて配置されます**。
*   `keywords`: 検索に使用される関連キーワードの配列。
*   `tag`: 施設のカテゴリを示すタグの配列（現時点では検索には直接利用されていないが、拡張の余地あり）。
*   `lat`, `lng`: Googleマップ連携のための緯度・経度座標。`合唱共用施設`(ID: 22)には`lat`/`lng`情報がなく、Googleマップ連携ができません。

### 2. レスポンシブデザインの切り替えロジック

*   **デバイス判定**: `isMobileDevice()`関数 が`window.innerWidth <= 768`に基づいてモバイルデバイスかどうかを判定します。
*   **表示切り替え**:
    *   `showInfo(infoId)`関数 は、`isMobileDevice()`の結果に応じて、情報パネル (`infoPanel`) またはボトムシート (`bottomSheet`) のどちらを表示するかを決定します。
    *   `window.addEventListener('resize')`イベントリスナー が設定されており、ウィンドウサイズ変更時に以下の処理を行います。
        *   既存のマーカーをクリアし、`generateMarkers()`を再実行して、新しいデバイス幅に合わせてマーカーの位置を再計算します。
        *   もし情報が既に表示中 (`activeInfo`がセットされている) であれば、現在のデバイスタイプに合わせて`showInfo()`を再呼び出しし、情報表示形式を自動的に切り替えます。
*   **CSSメディアクエリ**: `style_CSS.txt`では`@media only screen and (max-width: 768px)` と`@media print, screen and (min-width: 769px)` を用いて、モバイルとデスクトップで異なるスタイルを適用しています。

### 3. ボトムシート (`BottomSheet_JavaScript.txt`, `BottomSheet_CSS.txt`)

モバイルデバイスでのユーザーエクスペリエンスを重視した、複雑なボトムシートのインタラクションが実装されています。

*   **CSSによる基本設定**:
    *   `.bottom-sheet`は`position: fixed` で画面下部に固定され、`top: 100vh` で初期状態では画面外に隠れています。`height: 200vh` とすることで、コンテンツのドラッグやスワイプに必要な十分な高さが確保されています。
    *   `border-radius: 20px 20px 0 0` で上部の角が丸くデザインされています。
    *   `z-index: 3` により、背景マスク (`.mask`) より手前に表示されます。
    *   `.content`クラス に`overflow-y: scroll`が適用されており、コンテンツが長い場合にスクロール可能です。`scrollbar-width: none`と`-ms-overflow-style: none`、`::-webkit-scrollbar { display: none; }` により、各種ブラウザでスクロールバーが非表示にされています。
    *   スワイプインジケーターは`.bottom-sheet::before` 疑似要素で実現されています。
*   **JavaScriptによるインタラクション**:
    *   **状態管理**: `isOpened`, `isDragging`, `startY`, `lastTouchY`, `dragInitiated`, `isActiveScroll`, `scrollStartPosition`, `swipeStartY`, `isSwipeClosing`など、複数のフラグや座標を管理し、複雑な操作の状態を正確に追跡しています。
    *   **ドラッグ操作**: `dragStart`、`dragging`、`dragStop` の各関数が、`sheet-drag-bar`または`content`領域からのドラッグ操作を処理します。
        *   `dragging`中は`bottomSheet.style.transition = 'none'` を設定し、滑らかなリアルタイム移動を実現しています。
        *   `dragStop`では、ドラッグの最終位置 (`bottomSheetTop`) に応じてボトムシートを開くか閉じるかを決定します。
    *   **スワイプ操作 (閉じる)**: `handleSwipeStart`、`handleSwipeMove`、`handleSwipeEnd` の各関数が、ボトムシートを下にスワイプして閉じるジェスチャーを処理します。
        *   `deltaY > 0` (下向きスワイプ) の場合のみスワイプ動作を許可し、それ以外は無視されます。
    *   **スクロールとドラッグの競合解決**: `canInitiateDrag(deltaY)`関数 は、コンテンツのスクロール位置 (`content.scrollTop`) とドラッグ方向 (`deltaY`) に基づいて、コンテンツのスクロールとボトムシート全体のドラッグのどちらを優先するかを判断します。これにより、ユーザーがコンテンツをスクロールしようとしているのにボトムシート全体が動いてしまう、といった意図しない挙動を防ぎます。
    *   **開閉アクション**: `openAction()` と `closeAction()` は、ボトムシートの開閉時に`isOpened`フラグの更新、`document.body.style.overflow`による背景スクロールの制御、およびマスク (`.mask`) の表示/非表示を管理します。
    *   **ズームリセット**: `resetZoom()`関数 は、`openBottomSheet()` 呼び出し時に実行され、モバイルデバイスでのピンチズームをリセットし、UIの表示崩れを防ぎます。これは、ビューポートのメタタグを一時的に操作することで実現されています。
    *   **外部からの制御**: `window.openBottomSheet()`, `window.closeBottomSheet()`, `window.updateBottomSheetContent()` がグローバルに提供されており、`app_JavaScript.txt`など他のスクリプトからボトムシートを制御できるようになっています。
    *   **イベントリスナー**: `touchstart`, `touchmove`, `touchend`などのタッチイベントリスナーには**`{ passive: false }`** が設定されています。これは、ボトムシートのドラッグやスワイプ操作中にブラウザのデフォルトのスクロール挙動などを抑制するために必要です。

### 4. 情報パネル (`app_JavaScript.txt`, `style_CSS.txt`)

デスクトップ環境で表示される情報パネルに関する詳細です。

*   **CSSによるスタイリング**:
    *   `.info-panel` は`position: fixed`で画面左端に配置され、初期状態では`left: -400px` で画面外に隠れています。
    *   `active`クラスが追加されると`left: 0` となり表示されます。
    *   `minimized`クラスが追加されると、パネルの幅が`50px`に縮小され、`info-content`と`info-title`が非表示になります。
*   **JavaScriptによるインタラクション**:
    *   `showInfo()`関数 は、`infoPanel`に`active`クラスを追加し、`contentWrapper`（マップとパネルを包むコンテナ）に`panel-active`クラスを追加 することで、マップがパネルの分だけ右にずれるように調整します (`margin-left: 400px`)。
    *   `closeInfoPanel()`関数 は、これらのクラスを削除してパネルを閉じ、`activeInfo`をリセットします。
    *   最小化ボタン (`minimizeBtn`) は`infoPanel`の`minimized`クラスをトグルし、パネルの表示状態を切り替えます。
*   **アニメーション中の連続操作防止**: `isAnimating`フラグ が`showInfo`、`closeInfoPanel`、`minimizeBtn` で使用されており、アニメーションが完了するまで次の操作を受け付けないようにすることで、UIの不整合を防いでいます。

### 5. 検索機能 (`app_JavaScript.txt`, `style_CSS.txt`)

*   `searchAndShowInfo(query)`関数 は、`infoData`内の`title`、`keywords`、および施設IDを基に検索を実行します。
*   **重複結果の防止**: `seenTitles` `Set` を使用することで、同じ施設がキーワードとIDの両方でヒットした場合でも、検索結果に重複して表示されないように制御しています。
*   **リアルタイム検索**: `searchBox`の`input`イベントリスナー 内で`setTimeout`によるデバウンス処理 が実装されており、ユーザーの入力が一時的に停止した後に`searchAndShowInfo`が実行されます。
*   **タグ検索**: `narrowSearch`関数 は現在実装されていませんが、将来的にタグによる絞り込み機能を追加するためのプレースホルダーとして存在しています。

### 6. Google マップ連携の注意点

*   ナビゲーションボタン (`.navigation-button` および `.panel-navigation-button`) のクリックイベントリスナーは、`showInfo()`関数が呼び出されるたびに再設定されます。
*   これは、既存のボタン要素を`cloneNode(true)` でクローンして新しい要素に置き換えることで、以前のイベントリスナーが残らないようにし、重複してイベントが発火するのを防ぐためです。

### 7. フロアマップモーダル (`app_JavaScript.txt`, `style_CSS.txt`)

*   `document.addEventListener("click", ...)`内で`floor-button`クラスを持つ要素のクリックを検知 し、動的にモーダル要素 (`.image-modal`) を生成して`body`に追加します。
*   既存のモーダルがあれば、新しいモーダルを表示する前に削除されます。
*   モーダル内の「×」ボタン (`.close-modal`) をクリックすると、モーダルが削除されます。

### 8. IPアドレス制限 (`index_HTML.pdf`)

*   `index_HTML.pdf`の`</body>`タグの直前 に、JavaScriptで実装されたIPアドレスチェックのスクリプトが埋め込まれています。
*   `fetch("https://checkip.amazonaws.com")` を使用して、クライアントのグローバルIPアドレスを取得します。
*   取得したIPアドレスが`allowedPrefixes`配列 に定義されたプレフィックス（例: 大学のWi-FiのIP範囲）のいずれかに前方一致するかをチェックします。
*   一致しない場合、アラートが表示され、`document.body.innerHTML`が書き換えられてアクセスが拒否されます。
*   **開発環境でこの制限が邪魔になる場合は、このスクリプトを一時的に無効化または削除してください。**

## セットアップ

1.  GitHubリポジトリをクローンします。
    ```bash
    git clone [リポジトリURL]
    ```
2.  クローンしたディレクトリに移動します。
    ```bash
    cd [プロジェクトディレクトリ名]
    ```
3.  `index.html`ファイルをブラウザで開きます。または、任意のローカルサーバー（例: Live Server VS Code拡張機能）を使用して開いてください。
    ```bash
    # 例 (PythonのSimpleHTTPServerを使用)
    python -m http.server
    ```
    その後、ブラウザで`http://localhost:8000`などにアクセスします。
    **注意**: IPアドレス制限のため、大学の指定されたWi-Fi環境下でないとアクセスできません。開発・デバッグ時にはIPアドレス制限のスクリプトを一時的に無効にすることをご検討ください。

## 今後の改善点

*   **タグフィルタリング機能の実装**: `narrowSearch`関数のロジックを完成させ、施設をタグで絞り込めるようにする。
*   **データ管理の改善**: `infoData`が`app_JavaScript.txt`内に直接記述されているため、データ量が増えると管理が煩雑になります。将来的に、施設情報を外部ファイル (JSONなど) から非同期で読み込む形にすることで、データの更新・管理を容易にできます。
*   **アクセシビリティの向上**: キーボードナビゲーションのサポートや、スクリーンリーダー向けのARIA属性の追加など、より多くのユーザーが利用しやすいように改善。
*   **テスト環境の構築**: 自動テストを導入し、機能追加・変更時のデグレードを防ぐ。
*   **画像パスの動的生成**: 現在、施設詳細の画像パスはHTML文字列として生成されていますが、より安全で柔軟な方法を検討する。
